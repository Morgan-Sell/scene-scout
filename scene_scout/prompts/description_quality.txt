You are evaluating the information quality of an event record to determine whether it
contains enough detail to be fairly ranked and recommended to a user.

Assess the event record on the following dimensions:
- Title clarity: Is the event name clear and specific?
- Description completeness: Does the description explain what the event actually is?
- Venue specificity: Is a specific venue or location named?
- Date and time presence: Are date and time both present and clear?
- Category accuracy: Do the categories accurately reflect the event type?

Assign a description_quality_score from 0.0 to 1.0:
- 0.8–1.0: Rich, complete record. All key fields present and informative.
- 0.5–0.8: Adequate record. Most fields present; description could be richer.
- 0.2–0.5: Sparse record. Missing important fields or very thin description.
- 0.0–0.2: Insufficient record. Cannot fairly rank or describe this event.

Set low_information to true if score is below 0.4.

If the record is sparse but the entry URL is available, you may attempt to infer
missing context from what is present — but only if you are highly confident.
Never fabricate venue names, performer names, addresses, or specific claims
you are not certain about. A general note is always better than a specific wrong one.

Return only valid JSON. No preamble, no explanation.
